# LUNA 二进制组件

本文面向维护 LUNA 二进制组件及 QEMU 接入层的贡献者。

LUNA 后端以版本化静态库随仓库提供，构建使用与宿主平台匹配的归档和清单。
公开接口位于 QEMU 子模块。原组件实现与内部数值参考由私有组件仓库维护；
VenusA 开发后端的源码和数值测试位于外部算子仓库的 `lisem-backend/`，复用其
`modules/luna_sim/` 实现，不把厂商源码或测试固件复制到 Lisem 运行包中。

## 文件与平台

- `qemu/include/lisem/luna.h`：版本化 C ABI。
- `assets/luna/<system>-<arch>/liblisem-luna.a`：普通机器码静态库。
- 同目录 `manifest.json`：版本、ABI、目标、库 SHA-256 与接口头文件 SHA-256。

目标名称使用 `darwin`、`linux`、`windows` 和 `aarch64`、`x86_64`。
每个平台单独构建，不跨架构混用。macOS 最低 15.0；Linux 的库使用 GLib
和系统 C 运行库；Windows 与 QEMU 使用一致的 MSYS2 CLANGARM64/UCRT64 ABI。
静态库成功链接不等于该平台整机已通过音频、网络或交互验收。

`tools/build_qemu.py` 在配置 QEMU 前校验目标、ABI 和两个哈希。组件缺失或
校验失败会明确停止，不使用占位实现、不静默下载或退回其它版本。

## 接入契约

`qemu/hw/misc/listenai_luna.c` 是共享 QEMU 接入层，芯片适配器负责地址、
时钟和中断连接。每个设备创建独立的不透明上下文，不读取内部结构，也不解析
内部命令参数。库只通过 `LisemLunaHost` 调用宿主。

- 内存回调使用 guest 地址和宿主缓冲，必须经过 QEMU 地址空间及其错误检查。
  不把 guest 地址直接转成宿主指针，不绕过总线写回与代码失效。
- SHA-256 回调返回 64 个十六进制字符加终止符；处理每次请求的实际字节。
- 定时回调把相对延迟转换为 QEMU 虚拟截止时间。只在到期事件调用
  `lisem_luna_complete`；计算已经完成不代表可以提前交付结果。
- 复位取消定时事件和未完成输出；不能在取消后调用旧完成回调。
- `lisem_luna_read_safe` 只声明无副作用的状态读取。是否允许加速仍由 QEMU
  的访问权限、调试状态及计数策略决定，不能绕过 GDB/PMP 的回退路径。
- `fatal` 回调记录错误并终止当前运行，不能返回成功继续执行。
- 上下文与回调在设备执行线程上串行使用；回调表复制后，其 opaque 对象必须
  保持有效。销毁前停止所有定时回调，不跨实例共享状态。

manifest 可用布尔字段 `venusa_factory` 声明可选的
`lisem_luna_create_venusa(const LisemLunaHost *)` 工厂。共享接入层仅在经过
清单校验的组件声明此能力时选择它；Arcs 始终使用原工厂。此扩展不改变 ABI 1
的回调结构或原有函数签名，旧平台组件不需要提供新符号。

Linux x86_64 的开发组件使用独立 VenusA 引擎，并封装原 0.5.1 组件保持
Arcs 兼容。当前原始 pocket_dsp 固件在两种 JPEG 输入下通过完整推理链路验证，
已更新该平台资产。其他平台尚未重建；这不是全平台新版本发布。

ABI 不匹配必须拒绝创建。新增字段、改变函数签名或结构布局需要发布匹配
的新 ABI 与全部目标库；不能只修改公开头文件强行编译。

## 命令兼容

Arcs 支持已识别的向量算术、归约、比较、复数、矩阵、搬运、激活函数与
softmax，以及 64／128／256／512 点实数和复数 FFT。卷积族包含 4／8 位
权重、8／32 位输出、偏置、PReLU、逐通道量化、填充、步长和分块；池化
保留原厂的累加与移位语义。

VenusA 支持已识别的向量、复数、矩阵、张量搬运、整流、激活、查表、除法、
平方根与倒平方根，以及 64～1024 点实数和复数 FFT。卷积、逐通道卷积、
反卷积和池化支持相应的量化、填充、步长、分块与外部存储配置；输入和
权重可位于 SRAM、PSRAM 或 Flash，偏置及量化元数据使用权重所在的存储
总线。大尺寸步长 1 的高度分块反卷积在当前原厂库与实板上执行超时，
该参数组合暂不支持。

组件共用整数、矩阵、FFT 和激活计算，按芯片命令选择对应的布局与定点
规则。支持范围同时受命令布局、存储范围和工作量校验约束，未支持的
编码或布局会明确终止当前运行。具体覆盖以所选组件及其测试为准：开发版的
程序识别清单不代表全部参数组合已验证；外部算子仓库缺少等价实现的定制融合
程序、空控制接口及未支持的布局仍必须拒绝，不能借用相似算子冒充成功。
原始 pocket_dsp 固件还包含 `nlang` / `nnblas_runtime` 的寄存器传参内核。
开发组件从现有算法归档的指令、DWARF 和调用包装层还原其 ABI，使用经审阅的
程序体 SHA256 识别，复用参考算子完成数学运算；切片通过真实 DMA2D 执行。
这不依赖固件链接地址，也不需要修改固件或补齐原始私有源码。当前链路通过不
代表所有内核模式均通过：非标准除法、直接深度卷积 RELUx 等仍明确拒绝。
功能性完成延迟不是硬件标定，虚拟运行帧率不能作为实机性能结果。

原厂 C API 可能在 CPU 上计算、重排参数或拆分多次硬件命令。验证以原厂
归档生成的实际命令为入口，结合独立数值参考和真机输出检查；函数名称
相同不代表不同芯片、库版本或参数布局可以互换。数值覆盖与完整固件的
推理、音视频和联网验收分别保留证据。

## 更新与验收

维护者导入同一组件版本的全部平台归档、manifest 和接口头文件，作为一次
完整提交。版本更新不得混入源码、调试文件、LTO bitcode 或内部来源元数据。
保留 Linger 的 Apache-2.0 归属和许可；它的相关系数用于组件实现。

Linux 开发后端可在算子仓库的 `lisem-backend/` 中运行
`python3 build.py --guest-sdk /path/to/firmware-sdk` 生成候选归档。构建会验证
真实 guest 微程序字节、执行协议和数值测试，并运行 sanitizer；通过后才生成
候选 manifest，不自动安装。替换前备份旧库与清单，同步更新 SHA-256 后重建
QEMU，并执行 Arcs、VenusA 和原固件测试。不要把宿主算子测试通过解释为整机
推理通过。

完整发布的更新顺序：

1. 核对所有目标 manifest 的版本和 ABI 一致，核对库与头文件 SHA-256。
2. 运行 `make test`，重新构建 QEMU，运行 `make check-qemu`。
3. 使用实际发布 LPK 验证启动、推理、持久化和复位；再验证连续录播、AEC
   参考及宿主网络同时运行。测试命令见 `docs/development.md`。
4. 用相同输入串行比较更新前后的完整报告、UART、屏幕、DAC 和报文输出。
   数值或兼容行为确需变化时，说明预期差异；不修改参考结果掩盖回归。
5. 在每个声明支持的平台做原生构建和实际运行，再更新发布包。

组件异常优先保留版本、宿主平台、可复现输入、虚拟时序、寄存器访问和错误
日志。共享复现材料前移除用户凭据及业务数据。不要在接入层按固件地址、
微程序指纹或业务场景伪造结果来绕过组件问题。
